Help

HelpLast reviewed 2026-07-312 min read

Four pages for when something breaks, when a word makes no sense, or when you need to know what is actually switched on before you spend anything.

Something is not working, a word makes no sense, or you want to know what is real before you sign anything. These four pages answer those questions in plain words, and they say "no" and "not yet" where that is the honest answer.

Where to go first#

If a message on your screen has stopped you, start with troubleshooting. It is arranged by what you see, not by which part of the code produced it.

If you are deciding whether to take part at all, start with what is running today. The protocol is written and tested, but the public read index is not switched on, and no released wallet knows what a is. Knowing that before you spend a fee is worth more than any other page here.

The four pages#

Troubleshooting and common errors What the message means, why it happened, and the next thing to do.

Questions worth asking Short answers to what people actually ask, including the ones where the answer is no.

Complete glossary Every word this documentation uses, defined once, with links to where each one matters.

What is running today The package, the application, the index, wallets, and explorers, checked on 31 July 2026.

What is not on these pages#

No live numbers. There is no public index to read, so any count of , paths, or contributions on this site would be invented. Where a count belongs, these pages link to what is running today instead.

No wallet walkthroughs. No released wallet recognises ChainBloom outputs, so there is no true sentence of the form "your wallet will show you X". What you get instead is what to check yourself before you sign, in wallet connection and review.

No reassurance about money. Taking part costs a real Bitcoin miner fee, plus 1,000 satoshis held in each path output while that path is alive. A confirmed action cannot be undone by anyone, including the people who wrote this. Fees and confirmation gives the real numbers.

The full list of every code the protocol can emit lives in the error reference, with the rule behind each one and the file it lives in.
